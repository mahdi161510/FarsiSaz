# FarsiSaz — فارسی‌ساز بازی Mafia III

پروژه‌ی ترجمه و **بومی‌سازی** کامل متن‌های بازی *Mafia III* (نسخه‌ی Definitive Edition)
به فارسی. منبع ترجمه، دو فایل جدول رشته‌های بازی است:

| فایل | محتوا | آیتم‌ها |
|---|---|---:|
| `stringtable_en_common_group.xml` | همه‌ی متن‌های مشترک (داستان، دیالوگ، منو، اهداف) | ۱۰۴٬۵۵۲ |
| `stringtable_en_pc_group.xml` | متن‌های مخصوص پلتفرم PC (دسته، پروفایل، محتوای اضافی) | ۱۰۱ |

از این ۱۰۴٬۶۵۳ آیتم، **۵۰٬۵۲۵ رشته‌ی یکتا** وجود دارد (بقیه تکراری‌اند).
ترجمه فقط یک‌بار برای هر رشته‌ی یکتا انجام می‌شود و بعد به‌صورت خودکار روی همه‌ی
موارد تکراری اعمال می‌گردد.

> شده است. فایل‌های انگلیسی زیر `source/` دست‌نخورده می‌مانند.

## روش کار

```bash
python3 -m pip install -r requirements-gfx.txt   # یک‌بار؛ شکل‌دهی RTL و ابزار فونت
python3 tools/extract.py          # ۱. ساخت فهرست مادر و فهرست کار
python3 tools/extract.py --range C1-C100   # دیدن رشته‌های یک بازه
#    ... ترجمه‌ها در translations/batches/bNNN_*.tsv نوشته می‌شوند ...
python3 tools/credits.py          # ۲. ترجمه‌ی خودکار عنوان‌های تیتراژ
python3 tools/build.py            # ۳. ساخت فایل XML فارسی در ریشه‌ی مخزن + اعتبارسنجی
python3 tools/xbin.py             # ۴. ساخت فایل باینری xbin (همان فایل بازی)
python3 tools/export.py           # ۵. گزارش پیشرفت
python3 tools/review.py --port 8000        # ۶. بازبینی چشمی ترجمه‌ها در مرورگر
```

### فرمت بچ ترجمه

هر فایل داخل `translations/batches/` یک TSV ساده است:

```
# توضیح اختیاری (سطرهای # نادیده گرفته می‌شوند)
C8629	اطلاعات
C30208	کسب‌وکارهای خلاف
P5	حساسیت دسته
```

* ستون اول: شناسه‌ی رشته (`C…` برای common و `P…` برای pc) از `work/index_*.tsv`
* ستون دوم: متن فارسی
* شکست خط داخل متن با `\r\n` (چهار نویسه) و تب با `\t` نوشته می‌شود
* بچ‌هایی که نامشان دیرتر می‌آید اولویت دارند؛ پس اصلاحیه را می‌شود در بچ جدید گذاشت

## ضمانت‌های «خراب نشدن فایل»

`tools/build.py` بعد از هر ساخت، این موارد را بررسی می‌کند و در صورت خطا گزارش می‌دهد:

1. **خوش‌ساختی XML** — خروجی با پارسر XML آزمایش می‌شود.
2. **تعداد و ترتیب StringIDها** — باید دقیقاً مثل منبع باشد (فرمت xbin بازی
   آیتم‌ها را مرتب‌شده بر اساس هش StringID می‌خواهد؛ ترتیب دست نمی‌خورد).
3. **اسکلت فایل** — تگ‌ها، صفت‌ها، فاصله‌ها، `BOM` و پایان خطوط `CRLF` عیناً حفظ می‌شوند؛
   فقط متن بین `<Content Type="String">` و `</Content>` عوض می‌شود.
4. **توکن‌های فنی** — این‌ها باید عیناً در ترجمه بمانند و خودکار کنترل می‌شوند:
   * راهنمای دکمه‌ها: `#E_CTRL_MAP#`, `#E_MA_MAP_PLAYER#`, …
   * قالب‌ها: `%s`, `%S`, `%d`
   * ایندکس‌ها: `{0}`, `{}`
   * جداکننده‌ها و placeholderهای داخل کروشه: `[RET]`, `[ACTION]`, `[HORN]`, `[ROAR]`, `[RT]`, `[X]`
   * کنترل‌ها: `[HIT_1]`, `[ENTER_CAR]`, `[WEAPON_SELECT]`, `[QUESTION_ACTION]`, `[QUESTION_SELECT]`
   * مارکاپ: `&lt;bold&gt;` … `&lt;/bold&gt;`
   * علامت پول: `$` (تنها استثنا: `$%s` را می‌شود به `%s دلار` برگرداند)
5. **نویسه‌های کنترلی و `&` بدون escape** — اجازه ندارند وارد خروجی شوند.
6. **تعداد شکست خط‌ها** — در متن‌های چندخطی باید مثل منبع بماند.

رشته‌هایی که هنوز ترجمه نشده‌اند **انگلیسی می‌مانند**، یعنی فایل خروجی در هر
لحظه از پروژه قابل استفاده است و بازی نمی‌شکند.

## نصب در بازی

فایل‌های باینری آماده در ریشه‌ی مخزن هستند — دیگر نیازی به ابزار جانبی برای تبدیل نیست:

| فایل | اندازه | وضعیت |
|---|---:|---|
| `stringtable_en_pc_group.xbin` | ۱۸٫۷ کیلوبایت | ۱۰۰٪ فارسی؛ RTL پیش‌شکل‌دهی شده |
| `stringtable_en_common_group.xbin` | ۶٫۵۰ مگابایت | فارسی؛ RTL پیش‌شکل‌دهی و شکست خطوط زیرنویس انجام شده |
| `fonts_en_pc.gfx` | ۱٫۷۳ مگابایت | گلیف‌های فارسی/عربی افزوده‌شده به پنج فونت |

مراحل نصب:

1. از فایل‌های `sds` که تغییر می‌دهید نسخه‌ی پشتیبان بگیرید.
2. با یک ابزار آرشیو `sds` (مثل
   [Mafia Toolkit](https://github.com/Greavesy1899/MafiaToolkit) یا
   [Mafia3-SDS-Tool](https://github.com/Outsidev/Mafia3-SDS-Tool))، آرشیو
   `string_tables` را باز کنید و دو فایل
   `stringtable_en_common_group.xbin` و `stringtable_en_pc_group.xbin`
   را در همان مسیر داخلی جایگزین کنید.
3. در آرشیوی که نسخه‌ی اصلی `fonts_en_pc.gfx` را در نصب شما نگه می‌دارد، همان
   فایل را با نسخه‌ی این مخزن جایگزین کنید؛ نام و مسیر داخلی را دقیقاً حفظ کنید.
   فایل GFX را به‌صورت فایل آزاد کنار بازی نگذارید و ساختار SDS را جابه‌جا نکنید.
4. زبان بازی را روی English بگذارید.

> مسیر و نام SDS حاوی `fonts_en_pc.gfx` هنوز روی نصب واقعی بازی تأیید نشده است؛
> آن را حدس نزنید. فهرست فایل‌های نصب یا تصویر مسیر را برای تعیین محل دقیق لازم
> داریم. خود فونت و XBin از نظر ساختاری آزمایش شده‌اند، اما هنوز در بازی اجرا نشده‌اند.

## پشتیبانی فونت فارسی

فایل ریشه‌ی [`fonts_en_pc.gfx`](fonts_en_pc.gfx) پنج `DefineFont3` اصلی را نگه می‌دارد
(IDهای 1، 3، 5، 7 و 9) و به هرکدام گلیف‌های فارسی/عربیِ متناظر با شکل‌دهی افزوده
می‌کند؛ فونت‌ها، شناسه‌ها، گلیف‌های قدیمی، ترتیب تگ‌ها و تگ‌های غیرفونتی حفظ شده‌اند.
برای وزن‌ها از Vazirmatn استفاده شده است: ID 1 و 9 ← Medium، ID 3 ← Regular،
ID 5 ← ExtraBold و ID 7 ← Bold. برای هر فونت ۳۵۶ کدپوینت تازه افزوده شده است.

`tools/xbin.py` به‌طور پیش‌فرض متن‌های RTL را هنگام ساخت باینری شکل‌دهی و از نظر
ترتیب بصری بازچینی می‌کند. XML و بچ‌های ترجمه تغییر نمی‌کنند و خوانا می‌مانند؛
توکن‌های قالب، راهنماهای دکمه، `[HORN]`، `[ROAR]`، `[RT]`، `[X]`، markup و پایان‌خط‌ها
در آزمون‌ها حفظ شده‌اند.

### شکست خطوط زیرنویس (tools/wrap.py)

ویجت زیرنویس در بازی یک کادر چپ‌به‌راست است: متن را از ابتدای رشته می‌شکند. چون
متن فارسی هنگام بسته‌بندی پیش‌شکل‌دهی و بازچینی می‌شود، «ابتدای رشته» همان پایانِ
منطقی جمله است و نتیجه این بود که خط اولِ نمایش **دنبالهٔ جمله** می‌شد و بازیکن
باید از پایین به بالا می‌خواند؛ نام گوینده هم از لبه‌ی راست فاصله می‌گرفت.

`tools/wrap.py` در زمان ساخت xbin خودش خط‌ها را می‌شکند (حریصانه، بر پایه‌ی واژه‌ها
و با متریک واقعی فونت بازی از `fonts_en_pc.gfx`). عرض کادر با دو نمونه‌ی تصویری
زیرنویس دوخطی خود بازی کالیبره شده و حد پیش‌فرض **۳۰٫۱ em** است — کمی کمتر از عرض
واقعی کادر تا ویجت هرگز خودش دوباره نشکند. نتیجه:

- خط اول = شروع جمله (در RTL: لبه‌ی راست) و خط‌های بعد به ترتیب، پایین‌تر؛
- نام گوینده در سمت راست سطر اول: موتور بازی خودش «نام: » را پیش از متن می‌چسباند و آن نام ته سطر (لبه‌ی چپ) می‌افتاد؛ چون رشته‌ی نام را در دست داریم،
  `pad_speaker_label` انتهای منطقیِ ۳۵ نام گوینده را با فاصله پر می‌کند تا بازچینی RTL آن‌ها را به ابتدای رشتهٔ ذخیره‌شده ببرد و نام لبه‌ی راست بنشیند (عرض هدف ۲۹٫۳em < حد ۳۰٫۱em)؛
- شکست‌های دستی `\r\n`، `[RET]`، فهرست‌های مسیر، متن تیتراژ و رشته‌های دارای
  markup دست‌نخورده می‌مانند؛ فقط زیرنویس/ژورنال/راهنمای درون‌بازی بازچینی می‌شود؛
- قابل تنظیم: `python3 tools/xbin.py --wrap-em 28` یا خاموش‌کردن کامل با
  `python3 tools/xbin.py --no-wrap`.

برای بازسازی فایل GFX، نسخه‌ی اصلی `fonts_en_pc.gfx` و فایل‌های ایستای TTF از
[Vazirmatn](https://github.com/rastikerdar/vazirmatn) را محلی تهیه کنید. پوشه‌ی
TTF باید فایل‌های `Vazirmatn-Regular.ttf`, `Vazirmatn-Medium.ttf`,
`Vazirmatn-Bold.ttf` و `Vazirmatn-ExtraBold.ttf` را داشته باشد؛ سپس:

```bash
python3 -m pip install -r requirements-gfx.txt
python3 tools/gfx_font.py path/to/original/fonts_en_pc.gfx path/to/vazirmatn-ttf fonts_en_pc.gfx
```

مجوز OFL و انتساب Vazirmatn در [`Vazirmatn-OFL.txt`](Vazirmatn-OFL.txt) آمده است؛
این مجوز مربوط به گلیف‌های افزوده‌شده است، نه فونت‌های اصلی بازی. فایل GFX کامل
همچنان داده‌های بازی را در خود دارد؛ از آن فقط در کنار نسخه‌ی قانونی Mafia III
استفاده کنید. جزئیات در [`FONT-LICENSES.md`](FONT-LICENSES.md) آمده است.

> **وضعیت آزمون:** ساختار GFX، جدول کدپوینت‌ها، متریک‌ها و shape recordهای گلیف‌های
> افزوده‌شده بررسی شده‌اند؛ پشتیبانی موتور، برش متن و ظاهر نهایی هنوز داخل بازی
> آزمایش نشده‌اند.

## فرمت باینری xbin

`tools/xbin.py` همان قالب باینری خودِ بازی را می‌سازد. چیدمان بایت‌ها
(همه little-endian) از دو پیاده‌سازی مستقل استخراج و با هم تطبیق داده شده است:
[MafiaXbinTool](https://github.com/rm-NoobInCoding/MafiaXbinTool) (مخصوص بومی‌سازی Mafia III)
و [MafiaSdk](https://github.com/midoriiro/MafiaSdk) (کلاس‌های `XBin` و `StringTable`).

```
آفست  اندازه  محتوا
0     8       FileID      = 0x5E42EF29E8A3E1D3   (هش نوع StringTable)
8     8       FileVersion = 4
16    4       -1
20    4       EntrySize   = 16
24    4       تعداد آیتم‌ها (int32)
28    8       تعداد آیتم‌ها (uint64؛ ۴ بایت دوم = Unk0 اولین آیتم = 0)
36    16×N    برای هر آیتم: StringID (uint64) + Offset (uint64)
…     بقیه    رشته‌های یکتا: UTF-8 + بایت NUL، به ترتیب نخستین استفاده (بدون پیشوند طول)

Offset_i = (N - i) × 16 + string_offset_i − 8
مکان متن_i = (36 + 16×(i+1)) + Offset_i − 8
```

`string_offset_i` جایگاه رشته در pool متنی است؛ رشته‌های یکسان فقط یک‌بار ذخیره
می‌شوند و چند ردیف می‌توانند به همان بایت‌ها اشاره کنند.

سه نکته‌ی حیاتی که در این ابزار رعایت شده:

* **ترتیب آیتم‌ها** باید صعودی بر اساس `StringID` باشد (بازی با هش جست‌وجو می‌کند).
  `xbin.py` اگر ترتیب رعایت نشده باشد، با خطا متوقف می‌شود.
* **آفست‌ها نسبی‌اند** (نسبت به مکان خودِ فیلد آفست)، پس با عوض شدن طول متن‌ها
  در فارسی همه‌شان از نو محاسبه می‌شوند.
* **متن‌ها UTF-8 هستند**، نه Latin-1؛ برای همین حروف فارسی و نیم‌فاصله سالم می‌مانند.
  همچنین برخلاف پارسرهای XML، `\r\n` ها به `\n` تبدیل نمی‌شوند.
* **RTL فقط در باینری شکل‌دهی می‌شود:** `pack` و `patch` به‌طور پیش‌فرض حروف فارسی را
  پیش‌شکل‌دهی و Bidi می‌کنند؛ `--compare` و `--diff` متن خام را می‌سنجند و XMLها
  دست‌نخورده می‌مانند. برای غیرفعال‌کردن shaping در API پایتون از
  `pack_bytes(..., shape_rtl=False)` استفاده می‌شود.

### بررسی درستی

```bash
python3 -m pip install -r requirements-gfx.txt
python3 tools/xbin.py --test      # رفت‌وبرگشت خام و مسیر شکل‌دهی‌شده برای هر دو XML
python3 tools/xbin.py             # ساخت xbinهای ریشه و تأیید خروجی شکل‌دهی‌شده
python3 tools/xbin.py --wrap-em 28  # شکستن خطوط با حد باریک‌تر (زیرنویس کوتاه‌تر)
python3 tools/xbin.py --no-wrap     # فقط شکل‌دهی RTL، بدون شکستن خطوط
python3 tools/xbin.py --compare path/to/original/stringtable_en_pc_group.xbin
                                  # مقایسه‌ی بایت‌به‌بایتِ مسیر خام با فایل اصلی
python3 tools/xbin.py --diff path/to/original/stringtable_en_pc_group.xbin source/stringtable_en_pc_group.xml
python3 tools/xbin.py --patch original.xbin translated.xml patched.xbin
python3 tools/xbin.py --unpack in.xbin out.xml    # تبدیل xbin به XML (برای بازبینی)
```

`--test` روی فایل‌های واقعی اجرا شده است: ۱۰۴٬۵۵۲ آیتم common و ۱۰۱ آیتم PC
بدون تغییر در مسیر خام بازخوانی شدند، XML بازتولیدشده بایت‌به‌بایت برابر ماند و
مسیر RTL شکل‌دهی‌شده نیز برای همه‌ی آیتم‌ها تأیید شد. در اعتبارسنجی این ساخت،
`--compare` با هر دو فایل اصلیِ ارائه‌شده بایت‌به‌بایت موفق بوده است؛ فایل‌های اصلی
به‌دلیل حجم/منشأ بازی در این مخزن منتشر نمی‌شوند.

## تصمیم‌های بومی‌سازی این پروژه

* **لحن فحش و توهین: ملایم‌شده.** فحش‌های رکیک با معادل‌های قابل‌چاپ فارسی
  («لعنتی»، «بی‌شعور»، «عجب گندی») و توهین‌های نژادی دوران ۱۹۶۸ با
  «سیاه‌پوست»/«رنگین‌پوست» یا اشاره‌ی غیرمستقیم برگردانده می‌شوند؛ لحن خشن و
  کوچه‌بازاری دیالوگ حفظ می‌شود ولی واژه‌های تحقیرآمیز تاریخی به کار نمی‌روند.
* **اعتبار فارسی‌ساز:** عبارت «ترجمه و فارسی‌سازی توسط UnrealGame.ir» به متن
  حقوقی بازی (هر دو بلوک کپی‌رایت در common و pc) و به پایان تیتراژ اضافه شده است.
* **اسامی خاص** (شخصیت، مکان، برند، سلاح، خودرو) آوانگاری می‌شوند و در
  `translations/GLOSSARY.md` ثبت می‌گردند تا در همه‌ی بچ‌ها یکسان بمانند.
* **نام آهنگ‌های رادیویی** (رشته‌های داخل نقل‌قول مثل `"Caroline"`) به‌صورت
  اصلی نگه داشته می‌شوند، مگر اینکه نام مأموریت باشند.
